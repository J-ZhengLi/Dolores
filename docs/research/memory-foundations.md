# Memory foundations for Dolores

Research date: 2026-10-07. Planning evidence, not an implemented memory system or a biological model. The user's desired experience is automatic, useful remembering behind a simple enable/disable switch. This note separates scientific findings from proposed software requirements.

## What human memory suggests

Humans do not reliably preserve a complete recording of every conversation, image or sensation. In an original divided-attention experiment, people missed a conspicuous unexpected event while concentrating on another task. Encoding depends on attention; retrieval is also selective. The useful part of the user's analogy is keeping a small working set and finding relevant material through cues, rather than copying an entire archive into every interaction. [Simons and Chabris, 1999, original experiment](https://www.chabris.com/Simons1999.pdf).

| Finding and its limits | Design implication for Dolores — an inference |
| --- | --- |
| Working-memory experiments support a small capacity under controlled conditions; Cowan's synthesis discusses approximately three to five chunks and the importance of task conditions and chunking. This is not an LLM token limit. [Cowan, 2001](https://www.cambridge.org/core/services/aop-cambridge-core/content/view/44023F1147D4A1D44BDC0AD226838496/S0140525X01003922a.pdf/magical_number_4_in_shortterm_memory_a_reconsideration_of_mental_storage_capacity.pdf). | Keep active context bounded. Retrieve a few useful items and fetch their sources when more detail is needed; do not select software limits from a biological chunk count. |
| Episodic memory concerns experienced events and their context; semantic memory concerns organized knowledge. Their relationship is more complex than two independent storage buckets. [Tulving's own account of the distinction, 1987](https://garfield.library.upenn.edu/classics1987/A1987K743800001.pdf), [Tulving, 2002](https://pubmed.ncbi.nlm.nih.gov/11752477/). | Separate source-linked task/conversation episodes from revisable preferences and facts. A successful task is evidence of an outcome; an inferred preference is a hypothesis. |
| Retrieval cues interact with how an event was encoded; a strong general association is not always an effective cue. The original paper studied episodic retrieval using verbal material, not vector databases. [Tulving and Thomson, 1973](https://doi.org/10.1037/h0020071). | Index project, task, time, entities and source identifiers as well as semantic similarity. Preserve enough context to distinguish similarly worded events. |
| Memory can reconstruct and distort remembered events, including false recognition and misattribution. [Schacter, Norman and Koutstaal, 1998, author research review](https://pubmed.ncbi.nlm.nih.gov/9496626/). | Summaries need provenance, confidence and correction. Never present a generated interpretation as a verbatim past statement; reopen source evidence when accuracy matters. |
| Original visual-learning experiments found improvement dependent on post-training sleep under their task conditions. This demonstrates offline processing in that setting, not a requirement to imitate sleep in software. [Stickgold et al., 2000](https://pubmed.ncbi.nlm.nih.gov/10771409/). | Consolidate bounded new material outside the foreground request, with deduplication and versioning. Preserve source links when compressing episodes into useful knowledge. |
| Practicing retrieval of some items impaired subsequent recall of related unpracticed items in controlled experiments. This is not proof that software should erase old records. [Anderson, Bjork and Bjork, 1994, original experiments](https://bjorklab.psych.ucla.edu/wp-content/uploads/sites/13/2016/07/Anderson_RBjork_EBjork_1994.pdf). | Limit repeated retrieval of popular items, retain diverse evidence and mark superseded facts. Distinguish retrieval ranking from actual deletion. |

The brain's mechanisms do not establish that retaining only an index is sufficient: an index needs surviving evidence to resolve to. Dolores should explicitly define which source records are retained, for how long, and what happens when they are deleted or unavailable.

## Relevant agent evidence

*Generative Agents* used a natural-language memory stream, retrieval scored by relevance, importance and recency, and reflections linked to supporting memories. Top-ranked items fitting the model context informed behavior. Ablations supported these components' contribution to believable behavior in a small simulated town. The paper also reported embellished knowledge and noted that robustness against memory manipulation and hallucination was largely unknown. This is a useful architecture experiment, not proof of reliable personal-assistant recall, consciousness, secure scheduling or companionship quality. Its scoring constants should not become Dolores defaults without evaluation. [Park et al., 2023, sections 4, 6 and 8](https://arxiv.org/html/2304.03442v2).

## Proposed requirements to carry into planning

1. **Automatic learning:** enabling memory starts bounded extraction from eligible Dolores interactions and task outcomes, without requiring users to author memory entries. Exclude credentials; do not extend this to ambient sensory recording. Show last successful update, pending/error status and a retry action so silence cannot masquerade as learning.
2. **Resolvable evidence:** each episode/claim retains scoped source identifiers, event time, extraction version and confidence. A missing or deleted source is handled explicitly; summaries cannot manufacture replacement evidence.
3. **Useful retrieval:** project isolation precedes ranking. Use metadata plus semantic/lexical retrieval, bounded source expansion and a hard context allowance. Inspectable “why remembered” information supports corrections.
4. **Revisable knowledge:** user corrections outrank old inferred preferences. Store conflicting evidence and supersession rather than silently rewriting history. Inferences remain distinguishable from explicit user statements.
5. **Simple control:** one visible on/off control governs automatic capture and use. Disabling prevents queued writes and future retrieval; deletion is a separate understandable action covering derived summaries and indexes. Define restart and in-flight behavior before implementation.
6. **Measured reliability:** exercise relevant-event recall, incorrect-person/project collisions, changed preferences, unsupported claims, source deletion, interrupted writes and memory-off behavior. Compare against a no-memory baseline using bounded deterministic cases and real-model trials. Freeze budgets and acceptance thresholds per brick; do not infer reliability from a convincing anecdote.

Proactive conversation should consume this evidence through a separate opt-in policy with quiet hours, frequency/token bounds and dismissal feedback. A remembered unfinished task can motivate a suggestion, but does not itself authorize actions or prove the product design calls for a reminder now. The user's “Meta Muse” reference remains a competence goal; this research does not establish a specific product equivalence.
