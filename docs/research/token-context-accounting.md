# Token and context accounting for Dolores

Verified on 2026-10-02 against public upstream source: [Codex `ca466061`](https://github.com/openai/codex/tree/ca466061d64f0b44f416135c7fd06aa7af850bbc) and [DeepSeek Harness `639ed015`](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84). Codex findings describe its open-source engine and TUI; they do not establish private desktop-app implementation details. Recommendations below are Dolores design choices, distinguished from verified upstream behavior.

Neither fixed density formula is exact tokenization. In particular, a character count substantially underprices many CJK strings. OpenAI's token-counting API can count a complete Responses request, including tools, files, images, roles and boundaries; a plain-text tokenizer cannot fully price that structure. An OpenAI-compatible endpoint does not necessarily implement this optional API. [OpenAI Docs: counting tokens](https://developers.openai.com/api/docs/guides/token-counting)

## Percentages and policy are different quantities

**Codex:** the default usable capacity is `floor(rawWindow × 0.95)`. Its normal automatic-compaction limit is `min(configuredLimit, floor(rawWindow × 0.9))`, with the model default used when no explicit limit exists. The full usable window is checked independently of the selected automatic-compaction scope. [Model limits](https://github.com/openai/codex/blob/ca466061d64f0b44f416135c7fd06aa7af850bbc/codex-rs/protocol/src/openai_models.rs#L514), [Policy checks](https://github.com/openai/codex/blob/ca466061d64f0b44f416135c7fd06aa7af850bbc/codex-rs/core/src/session/context_window.rs#L81)

The TUI receives usable capacity, then normalizes the remaining percentage by a fixed 12,000-token baseline: `round(clamp(100 × max(0, (window − 12000) − max(0, lastTotal − 12000)) / (window − 12000), 0, 100))`; capacity at or below that baseline returns 0. This is a product-specific presentation convention, not a general budgeting formula. [Capacity emitted to clients](https://github.com/openai/codex/blob/ca466061d64f0b44f416135c7fd06aa7af850bbc/codex-rs/core/src/session/mod.rs#L4187), [Remaining percentage](https://github.com/openai/codex/blob/ca466061d64f0b44f416135c7fd06aa7af850bbc/codex-rs/protocol/src/protocol.rs#L2419)

**DSH:** the ring uses `min(100, round(100 × used / contextWindow))`, preferring projected prompt tokens over the last prompt sample; it returns no percentage until both numerator and capacity exist. This projection is explicitly advisory, including a documented possibility of pairing a fresh model capacity with an older route's pressure. [Ring arithmetic](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/client/ui-conversation/src/client/context-occupancy.ts), [Projection contract](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/llm/token-meter/src/projection.ts#L20)

DSH's actual compaction threshold is `floor(min(window × thresholdRatio, window − reservedCompletionTokens − headroomTokens))`. The default ratio is 0.8 and default compaction headroom is 65,536 tokens. Missing capacity or non-positive remaining budgets cause configuration errors; the compaction service remeasures after pruning/summarization. These defaults belong to DSH's policy and should not be copied blindly into a smaller-context client. [Budget resolution](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/compaction/compaction-basic/src/config.ts#L142), [Enforcement](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/compaction/compaction-basic/src/index.ts#L307)

## Recommended Dolores contract

1. Add optional per-model `contextWindowTokens`, editable when adding or editing a model. Store an unset field as unknown. Validate set values as positive integers. Keep maximum response tokens separate. Prefer an explicit user override over verified provider/catalog metadata; never infer capacity from a model name alone.
2. Keep provider-reported request usage, cumulative session usage, and before-send request estimates as distinct values. Preserve the original usage record. Cache hits still occupy context; provider input counts may already include them. Reasoning may already be included in output. Normalize each provider once instead of adding cache/reasoning counters unconditionally.
3. Use a dependency-free Codex-style `ceil(UTF-8 bytes / 4)` estimate, adding explicit message framing and serialized tool-definition overhead. Price the **actual projected request**: system instructions, selected history, latest user input, tool calls/results and schemas. Mark this as estimated. Count media only when the adapter has a supported pricing rule; do not pretend an attachment's path or reference is its full token cost.
4. Show estimated request occupancy as `clamp(estimatedPrompt / rawContextWindow × 100, 0, 100)`, with numeric estimated tokens and capacity. Unknown capacity means an unavailable percentage, not zero or an invented denominator. Show last provider usage separately. Recompute on model selection and envelope changes; provider anchoring is optional later work and must be invalidated when its route or request structure changes. Avoid Codex's fixed 12,000-token display subtraction.
5. Reserve output and a deliberate safety margin before request-history selection: `promptBudget = contextWindowTokens − reservedOutputTokens − safetyMarginTokens`. A non-positive budget is an explicit configuration error. Retain the newest complete turns and mandatory instructions/input; preserve complete tool-call/result relationships. Keep full persisted history intact and remove old turns only from the request projection. If mandatory content alone does not fit, return a clear error instead of silently dropping it.
6. Treat lightweight estimates as the local policy's approximation, not a guarantee that the provider will accept the request. Handle the provider's context-overflow response explicitly. A numeric ring alone does not enforce a budget; enforce request selection using the same estimator used for the display, and show when older history was omitted. Automatic summarization can be added separately when that workflow is supported.

This recommendation follows the verified common pattern—configured model capacity, inexpensive request estimates, authoritative usage kept separately, and deliberate headroom—while retaining a clear distinction between display estimates and request enforcement.

## Selected product default

The user subsequently requested that blank model capacity use 128K. Dolores therefore treats blank/null/missing overrides as **131072 tokens**, keeping the original estimate/provider distinction and allowing smaller or larger per-model overrides. This is an explicit product default, not inferred provider capacity. Dolores uses 5% headroom plus its configured response reservation; it does not copy Codex’s 12000-token display baseline or DSH’s fixed compaction reserve.
