# Dolores roadmap

Build one usable brick at a time. Each new brick needs a small design decision, scoped implementation, behavior checks, resource measurements where relevant, and an updated acceptance record. Commit each completed brick separately before proceeding to the next, as requested by the user. Do not equate compilation with product acceptance.

## Next iteration

Next: brick 6.4, long-task recovery. Investigate output truncation and loop exhaustion before changing defaults; preserve useful progress and make bounded continuation explicit. Brick 6.3 supports four saved local servers with two shared active external slots, stable identities and independent lifecycle controls. Capacity recovery preserves the current review while a sibling is disabled. Brick 6.2 supplies explicit masked credential bindings backed by the native vault; locked/missing keys require repair and a fresh review. Brick 6.1 supplies bounded local stdio tools with no installation or idle process; external effects remain outside the file journal and tool approval does not sandbox a server. Brick 5.3 makes exact retained skills portable through a user-chosen destination without changing activation or copying resources/receipts. Automatic selection, representative task/tool evaluation and general generated-skill quality remain unaccepted. Automatic preferences have an inspectable policy; summaries still require Generate and Save. Root AGENTS.md cannot grant tool permission. Keep release acceptance open for folder-picker/keyboard/IME/system-theme UAT, Windows/macOS/Linux CI and representative 2-core/4-GiB measurements. Earlier Flutter working-set observations exceed the provisional target. Exact tokenization/pricing remain separate work. Live Qwen and DeepSeek probes verify specific synthetic flows, not universal provider or learning reliability.
