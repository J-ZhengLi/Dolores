# Thread forks and managed context

Chat actions → Fork conversation copies history through a selected completed assistant turn, up to 100 turns and 1 MiB. The new chat shares the original working folder, including temporary folders. It does not copy drafts, active runs, permission grants, thread settings or summaries. Historical receipts remain evidence; paused continuation authority is removed. The copy is transactional and survives deletion of its parent. Files are shared, not isolated.

Automatic compaction is always enabled, including for chats with a legacy opt-out value. Session summary explains the behavior and retains manual review/correction controls, without an on/off switch. Before a send that would omit older turns, the host makes at most one tool-free summary request, capped at 1024 output tokens and 30 seconds. It locally narrows the source to a contiguous complete batch that fits the configured model window. The call consumes a model-call allowance; remaining task time is reduced. The host preserves the original goal literally, summary coverage, model/revision and recent run provenance. Full history and receipts stay local. Summaries remain fallible context and grant no authority.

Malformed, credential-like, truncated, oversized or failed results preserve the previous valid summary and draft. A valid summary may still be insufficient for a tiny window: the send stops with manual-summary/window recovery instead of looping. A single oversized instruction can also require shortening or a larger configured model window. Read-only context preview makes no model request. During ordinary agent tool loops, bounded context recovery preserves literal user instructions and operation receipts; exhausted recovery bounds retain existing checkpoint/ranged-read recovery without replaying tools. See [goal and context recovery](everyday-harness-implementation-plan.md#eh03-goals-checklist-and-long-context-recovery).

Instruction review includes the root and nested AGENTS.md files inside the chosen folder. Each nested snapshot is labeled with its relative path; it applies only beneath that path, with deeper guidance taking precedence there. Parent directories outside the chosen folder and includes are not read. Discovery excludes hidden/build/output dependency directories, walks at most four levels and 64 directories, includes at most eight nested files, and refuses aggregate guidance above 8 KiB. Changes require a fresh review. These bounds are disclosed coverage, not an exhaustive repository index.

Activated skills retain project-over-global precedence. The prepared context contains a bounded name/description catalogue and exact instructions only for skills matching the current draft by name or description keywords of at least four characters. Simple English singular/plural pairs such as review/reviews match in either direction; substrings such as preview/review do not. Mention a skill name to force selection. Context inspection shows selected snapshots; this is explicit keyword matching, not semantic retrieval. Activation, review and permission rules remain binding.
