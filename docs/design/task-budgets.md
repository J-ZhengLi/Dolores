# Task baselines and budgets

Brick 10.1 adds a versioned synthetic corpus and effective scoped task allowances. Model output/context configuration remains separate, including the 128K blank context default. No model switch or silent retry occurs.

`SettingsPatch.task` optionally supplies nullable `modelCalls` (2–128), nullable `toolCalls` (1–256), `segments` (1–8), and nullable `elapsedSeconds` (30–3600). Blank call counts mean Automatic; saved numeric limits are preserved. User → project → thread precedence, revisions, invalid-save preservation and frozen run settings reuse the scoped-settings contract. The default allows ordinary work to continue through model/tool cycles, with a resource checkpoint at 64 model calls or 128 tool attempts shared by parent/children, and four explicit continuation segments. Blank elapsed time adds no overall task deadline. An explicit task clock bounds active work independently of provider inactivity; pending root or child approval excludes review time. Expiry saves a paused result, cancels pending work, preserves completed receipts and never replays uncertain effects. Desktop-control handoffs freeze effective numeric limits and retain their separate finite expiry.

The final available model call reports results without tools. Resource/context checkpoints and explicit tool/step/output limits retain the partial response and receipts. Each explicit Continue increments the saved segment count, uses fresh preparation/decisions and never replays pending calls. At the segment ceiling, change Task limits deliberately after reviewing saved work; refusal occurs before another provider request. Legacy paused messages start at segment one. Per-run event capacity is 2048 plus the reserved terminal marker, covering the largest supported operation allowance and reviews; reads and retention remain bounded. Continuation input remains byte bounded, so many large receipts can require compaction or a summary/new chat rather than an endless extension.

Failure detection stops before a third identical failed tool request, or after six consecutive failed requests. Canonical argument JSON and the tool name identify retries independently of call IDs. Successful tool work clears the streak; nonzero/incomplete command receipts and MCP `isError` results are failures. The check also runs between queued calls, preventing later effects after a pause. Provider thinking, long human review and repeated successful reads do not count as failures. No-progress pauses retain their evidence and require a changed approach or resolved cause before explicit Continue. Declined one-use write/command/MCP previews are discarded through registry/logging/scoped adapters so they cannot fill a long run or retain execution authority.

`scripts/coding-baselines.py` freezes six cases: understand a project, repair unchanged checks, a two-file feature, an edit near the end of a larger file, limit recovery and Stop at approval. Prepare a fresh folder; evaluate actual files/reply against the external criteria. The evaluator runs fixed local checks with an isolated bytecode cache and deadline. It does not send model requests or automatically classify unknown causes. User-account commands can reach the evaluator, so this is a development baseline rather than an independently contained adaptation trial (12.2/13.1).

The older bounded live probe recorded in acceptance showed a five-operation repair with an explicit allowance.
