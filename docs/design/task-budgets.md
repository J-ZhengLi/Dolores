# Task baselines and budgets

Brick 10.1 adds a versioned synthetic corpus and effective scoped task allowances. Model output/context configuration remains separate, including the 128K blank context default. No model switch or silent retry occurs.

`SettingsPatch.task` optionally supplies `modelCalls` (2–16), `toolCalls` (1–32), `segments` (1–8), and nullable `elapsedSeconds` (30–3600). User → project → thread precedence, revisions, invalid-save preservation and frozen run settings reuse the scoped-settings contract. Defaults retain four model calls/four operations and four explicit continuation segments. Blank elapsed time adds no overall task deadline. An explicit task clock bounds active work independently of provider inactivity; pending root or child approval excludes review time. Expiry saves a paused result, cancels pending work, preserves completed receipts and never replays uncertain effects. Desktop-control handoffs retain their separate finite expiry.

The final model call reports results without tools. Exhausted tool/step/output limits retain the partial response and receipts. Each explicit Continue increments the saved segment count, uses fresh preparation/decisions and never replays pending calls. At the segment ceiling, change Task limits deliberately after reviewing saved work; refusal occurs before another provider request. Legacy paused messages start at segment one. Per-run event capacity is now 256 plus the reserved terminal marker to cover the largest supported operation allowance; reads and retention remain bounded. Continuation input remains byte bounded, so many large receipts can require a summary/new chat rather than an endless extension.

`scripts/coding-baselines.py` freezes six cases: understand a project, repair unchanged checks, a two-file feature, an edit near the end of a larger file, limit recovery and Stop at approval. Prepare a fresh folder; evaluate actual files/reply against the external criteria. The evaluator runs fixed local checks with an isolated bytecode cache and deadline. It does not send model requests or automatically classify unknown causes. User-account commands can reach the evaluator, so this is a development baseline rather than an independently contained adaptation trial (12.2/13.1).

The bounded live probe recorded in acceptance shows a five-operation repair succeeds with an explicit test allowance. It does not justify adopting larger defaults or establish broad task competence. Larger files, resume/forks, permission modes and attachments retain their separate 10.2–10.6 gates.
