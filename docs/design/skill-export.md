# Portable reviewed skills — brick 5.3

Open Skills, choose Project or Global, open Saved versions, and select the retained version to review. **Export SKILL.md** opens the native Save dialog. Choose or create a folder whose name matches the skill, then save as `SKILL.md`. For example, skill `review` exports to `review/SKILL.md`. The app requires an existing writable parent folder and an absolute destination; it does not create directories or choose a collection automatically. Cancel writes nothing.

The export is the exact saved document, including YAML metadata, Markdown, Unicode and original line endings. It works for imported and generated skills, disabled entries and older retained versions, even when their original file has changed or disappeared. Unsaved drafts and unretained file reviews cannot be exported through this action. The existing five-version retention applies; versions already pruned or forgotten are unavailable.

The host accepts a review token, session and destination, never client-provided instruction text or a substitute version. The five-minute review binds the original scope/folder, selected version and saved state. Expired, cancelled, replaced, wrong-session or changed-state reviews are refused before writing. Export retains the review for retry at another destination or separate activation. Engine command serialization excludes concurrent ordinary chat/skill mutations during publication; direct external database edits remain outside that guarantee.

The shared file-skill parser verifies the retained document's metadata matches the saved name/description before writing. Inconsistent legacy records are refused rather than rewritten. The 8-KiB bound remains. A temporary file in the chosen folder receives the complete text and is synced before atomic no-clobber publication. Existing files, empty files, directories and destination links are refused, including a destination created after the initial check. Failure removes the temporary file. Successful export changes no SQLite record, activation, source file, model setting, conversation or credential. No provider request, tool execution, dependency, watcher or schema migration is needed.

Only `SKILL.md` is copied. Evaluation receipts, source-chat quotes stored in receipts, model/provider settings and bundled resources are excluded. Any references already written inside the instruction document remain literal. Scripts/referenced files must be reviewed and transferred separately; standalone export does not promise a self-contained skill bundle. Export is local publication to the user's chosen path, not upload or automatic installation. Placing the file in another project's `.agents/skills/<name>/` or the global collection makes it discoverable there; it still requires Refresh, Review file and explicit activation in Dolores.

UI uses the existing inspector, palette and wrapping footer. Export is available only while reviewing a retained version with a valid token. Pending Save/export disables duplicate actions, closing and scope changes; chat changes remain locked throughout Skills. Success/failure scrolls a status message into view, including at compact widths. Errors keep the reviewed version available; an expired or changed review requires Refresh. Native Save dialog interaction, platform-specific input/accessibility and macOS/Linux remain separate acceptance work.
