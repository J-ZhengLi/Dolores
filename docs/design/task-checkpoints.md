# Task checkpoints and recovery

Run history exposes a checkpoint assembled from durable run snapshots, proposed operation reviews, tool receipts, terminal reason and unmatched effect intents. A proposed plan is unverified; returned receipts are not universal proof of task completion. Linked resumes preserve the original goal and namespace receipt IDs by run. All 257 bounded event slots, including the reserved terminal marker, are readable.

Prepare resume draft is explicit, refuses an occupied composer and requires the latest paused/failed/stopped/interrupted run. Send rechecks the source, constructs fresh tools and current configuration, counts the new segment and records its parent. Previous tool calls are never replayed. The recovery message carries bounded receipt previews and previous settings/tools, asks for inspection of current effects and retains complete local evidence. Missing ancestry, excessive depth or an oversized recovery request refuses with manual inspection/scoped-request guidance. This does not imply detached completion or a worktree.

Saved-chat drafts are local SQLite text bounded by the existing message allowance. The composer saves after 250 ms of quiet typing and flushes its captured draft on a chat switch. Sending durably saves the input before dispatch; a completed turn conditionally clears that submitted draft. Failed/interrupted work remains available after restart. No folderless unsaved-chat draft is persisted before a chat exists. A crash within the debounce interval can lose the newest unsent keystrokes; the visible save error retains text for copying or another edit/retry. Conversation exports do not include unsent drafts. Chat deletion cascades draft deletion.

Ordinary paused-message Continue remains available and its run is linked for checkpoint inspection. Changing model/configuration does not change the historical snapshot or confer new permissions. Commands/MCP can leave external effects after failure; inspect their actual state before resuming. Existing user-account containment limitations remain.
