# Implemented extension contracts

Brick 9.3 adds a bounded Rust registry for compiled components and reviewed external MCP adapters. Descriptors expose ID/version, host API range, execution kind, dependency IDs, capability requests, tool ownership, configuration revision, entry identity, enabled/available state and health. Compiled entries use the build revision and fixed registration revision 1; provider request settings are frozen separately. MCP entries use their reviewed server version, launch fingerprints without paths and actual configuration revision. A plugin label does not grant permission or establish containment.

Resolution uses deterministic dependency order. Unsupported APIs, missing/disabled dependencies and cycles disable the affected entries; unrelated registrations remain usable. Registration IDs/capacity and tool owners are validated. The host composes a fresh scoped registry from saved configuration; disabling/forgetting a connection removes its tools from future snapshots without idle discovery or launching a server. Health distinguishes compiled availability from an MCP manifest whose current server health has not been probed. MCP still starts only after an approved operation, with its existing deadline, credential/redaction and owned-process cleanup.

Each primary run stores the resolved descriptor snapshots. Its tool wrappers retain the actual adapter and registration references until the run finishes; new registries cannot retarget those wrappers. Retired registration hooks are released when the final snapshot drops. There are no new resident services, listeners or dynamically registered tasks. Existing adapter process ownership remains responsible for child cleanup.

The first typed seam is a compiled, pure synchronous ToolProposalHook, executed in dependency order. Hook errors refuse preparation/dispatch. Host validation sits outside hooks: a transformed prepared plan must equal the adapter's original plan, or preparation/review must restart. Exact IDs, resource snapshots and approval checks still apply afterward. Generated/external code cannot register hooks; MCP contributes tools only. This conservative seam deliberately does not yet permit executable proposal rewrites, context replacements, arbitrary UI contributions or asynchronous hook tasks.

This is an inventory and lifecycle foundation, not the target production loader, activation transaction or OS sandbox. Trial/activation/quarantine/rollback and broader typed hook families remain milestone 13 work. File/command/MCP effects are still governed by task approvals and actual adapter boundaries; full-access permission modes remain milestone 10.
