# Windows portable preview — brick 8.1

The preview is a local unsigned x64 ZIP assembled from the existing **normal** Flutter release. Build first; package separately. Its manifest labels build freshness unverified, so diagnostic/stale bundles are not silently described as normal fresh builds. The preview is not a published/signed release or clean-machine acceptance.

`python -I -B scripts/package-windows.py --directory <fresh-absolute-output-directory>` accepts exactly the reviewed runtime payload: launcher, Flutter/Rust/native-plugin DLLs, native-assets metadata, compiled Dart/ICU files and the current Flutter asset set including notices. Unexpected files, missing/empty files, symlinks/junctions, non-x64 PE binaries and oversized payloads refuse before publication. New runtime assets/plugins require a reviewed contract update.

The archive contains one `Dolores/` folder with the runtime, START-HERE, user guide, privacy notes, MIT license and per-file SHA-256/size manifest. Entries have fixed ZIP timestamps and generic file permissions; no source machine paths, user data, credentials, git author identity or raw test artifacts are added as metadata. The application and third-party assets themselves are build output and need independent release review.

The normal Windows build uses [Rust path remapping](https://doc.rust-lang.org/rustc/remap-source-paths.html) for workspace/home/toolchain locations. Flutter debug information is kept in a fresh ignored `output/release-symbols/` directory using [split-debug-info](https://docs.flutter.dev/perf/app-size); keep matching symbols privately for diagnosis. Class names are not obfuscated. During compilation only, the generated plugin-registrant directory gets a stable package URI in `.dart_tool/package_config.json`; the exact original bytes are restored on success/failure. This avoids the otherwise embedded absolute registrant URI without editing the SDK or generated Dart source. Build interruptions that kill the process cannot execute cleanup; run dependency preparation again before another build.

Packaging and archive verification scan UTF-8/UTF-16 bytes for the current workspace/home prefixes, including chunk boundaries, and refuse with rebuild guidance. This caught real compiler paths in the first bundle. It complements the file allowlist and independent secret scan; it does not classify all personal information or detect every foreign build-machine path. Symbols and PDBs are not package members.

Each source file is read in bounded chunks and checked for size/mtime changes. A temporary owned ZIP is verified before no-overwrite publication; the resulting archive gets a SHA-256 sidecar. Existing destinations refuse and remain intact. `--verify <zip>` checks exact entries, duplicates/size/encryption, manifest shape and content hashes without executing or extracting. Hashes detect corruption, not trusted authorship; users still need a trustworthy download source.

The destination requires separately installed [Microsoft Visual C++ x64 runtime](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170). The helper copies no system DLLs or installer and does not change Windows settings. This follows [Flutter's ZIP deployment guidance](https://docs.flutter.dev/platform-integration/windows/building#building-your-own-zip-file-for-windows) for shipping the complete runtime with C++ prerequisites available.

Portable refers to application files. Normal history/preferences remain in the existing account data location; vault keys keep their data-directory scope. Working folders are not included or migrated. Keep one app per data directory. Signing, complete dependency-license review, clean-machine/C++-missing recovery, accessibility, other platforms and representative low-end measurements remain release gates.
