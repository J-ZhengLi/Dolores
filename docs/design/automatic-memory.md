# Automatic preferences — brick 4.4

The selected Flutter host learns durable work and response preferences after a complete reply is saved. Learning is enabled by default; a global revisioned switch in Memory returns to manual review. Summaries still require Generate and Save. No idle worker, startup replay, indexing or backlog extraction is added.

One completed user message is eligible per reply, at most 8 KiB. Conservative English/Chinese first-person/future markers recognize explicit preferences. Ordinary tasks, temporary qualifiers, fenced/blockquote text, common credential/path/email and permission patterns skip the extra request. Other phrasings/languages may be missed. These are limited filters, not universal intent/privacy classifiers. Learning shares eligible source again with applicable existing preference title/text/enabled fields, using the same provider/model. Replies, tools, AGENTS.md, summaries, drafts, roots and origin quotes are excluded. Manually entered preference text is also local plaintext shared with the provider.

One tool-free extraction shares the runtime and active-run slot: 10 seconds, 512 output tokens or lower configured limits, and 8 KiB output. Shared token preparation respects model capacity, reservation and headroom. Mandatory overflow refuses before transport. The standard provider can resend an identical request once only for an explicitly rejected usage-reporting option; inference/output failures never retry automatically. Stop cancels learning while retaining the completed reply. Learning failures never erase the reply or restore/resend its draft. Trajectory records phase/result; Memory shows the current chat's latest attempt and separate reported learning usage. Missing usage stays unavailable.

Strict JSON returns at most three stable topics: Response style, Language, Code style, Testing, Commits, Tools. Text MUST equal its exact source quote (512 UTF-8 bytes maximum), preserving language, qualifiers and correction phrases. The host requires a direct first-person/future excerpt at a sentence boundary and topic vocabulary. Paraphrases, fabricated quotes, unknown/repeated topics, sensitive patterns and malformed output refuse the batch. This limits the semantic broadening observed in the earlier reviewed Qwen draft; it cannot prove correct topic selection. Entries remain fallible, inspectable and editable. The prompt explicitly distinguishes corrections from ambiguous conflicts.

Working chats save only in the current folder; side/legacy chats save in All chats. Existing folder-first 4-KiB retrieval and 12-entry/scope limits remain. Source is `automatic` with host session/message/quote/model/time provenance. `autoUpdate:true` marks untouched learned entries; legacy records default false. Free capacity permits creation; normalized exact duplicates make no write. Same-topic replacement requires an untouched enabled automatic entry plus an explicit correction marker (“from now on”, “instead”, “以后”, “改为”). Manual/reviewed entries and manually edited/disabled learned entries are protected. Edit/toggle preserves source/origin and clears replacement eligibility even after re-enabling. A newly stated explicit preference can be learned again after deletion.

Schema 13 adds a global policy and one latest attempt/watermark per chat. Claim the latest completed source before transport; completed/failed/interrupted/skipped/stopped attempts never replay. Saving verifies completed source, policy revision, all applicable preferences and claim identity atomically. Candidates/report commit together; failures roll back everything. Concurrent correction/deletion prevents recreation/replacement. Cancellation is checked at publication; completion wins once commit starts. Failed publication may retain an honest unfinished report without retry. Chat deletion cascades attempts but preserves preferences/source quotes. Preference deletion stops future retrieval without rewriting earlier reply provenance. External database edits are outside supported workflows.

Frozen and native loopback checks cover exact evidence/wire, scope, duplicates/conflicts/protection, stale snapshots/policy, replay, Stop/deadline, rollback, restart, deletion, limits and separate usage. Compact light/dark and renderer checks cover policy/activity views. Authorized Qwen probes assess specific synthetic learning/correction/follow-up behavior, without universal memory quality, secrecy, provider compatibility or OS input claims.
