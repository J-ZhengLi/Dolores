# Per-model generation profiles — brick 6.6

Request settings now edits one enabled model at the configured endpoint. Its dropdown starts with the active chat model; selecting another model in the dialog does not change the chat. Save persists output allowance, request timeout and an explicit reasoning adapter. Switching the composer model loads that model's profile. Restore defaults is local until Save and removes only that model's override. Cancel and failed Save retain the draft and previous saved profile.

Profiles use the exact endpoint/model pair. Unconfigured models inherit application settings (provider-default output and 180-second inactivity unless previously edited). Existing numeric allowances stay unchanged. Blank output omits the generation maximum; optional explicit values support 1–16777216 tokens, subject to provider support. Context remains separate, with blank using 128K. Automatic output reserves one quarter of the context window, capped at 32768, for local input planning only. Explicit output reserves the configured value. Inactivity excludes active decoded generation and approval review; an optional task clock counts active work separately. Tool/model step counts and file/transport bounds remain.

## Explicit reasoning adapters

Provider default sends no reasoning override and retains max_tokens. DeepSeek thinking off sends a top-level thinking object with type disabled. OpenAI low/medium/high send reasoning_effort and use max_completion_tokens instead of max_tokens. Model IDs and a listing cannot certify that a gateway supports or honors those fields. No capability is inferred from the model name, no extra arbitrary JSON is accepted, and successful HTTP alone does not prove a reasoning setting took effect. See [official contract research](../research/model-generation-controls.md).

DeepSeek explicit thinking on is unavailable until complete reasoning replay is supported. Some direct providers require reasoning_content history for tool loops; this harness does not preserve it. Provider default can still use reasoning on a compatible gateway, but this is not a claim of direct DeepSeek thinking-tool compatibility. Reported reasoning counts remain part of output usage and now appear in output-limit pause text; absent usage is unavailable rather than zero or proof of disabled thinking.

Named generation-parameter rejection gets a sanitized actionable error and a Request settings action. Controls are not silently removed or retried. The narrow existing stream_options compatibility retry remains for an isolated usage-field rejection; a response naming generation settings takes precedence and receives no retry. Malformed unfinished tool calls never reach approval and have explicit guidance to inspect completed changes and narrow the task or select another model. Completed effects remain; a failed turn restores the draft without storing a partial turn. This is manual recovery, not automatic JSON repair.

## Persistence and consumers

SQLite schema 17 adds model_request_settings without rewriting existing settings or transcripts. Default reasoning is omitted from serialized legacy settings and old metadata; unknown enum values are refused. Save is transactional and bound to the current endpoint/enabled model set. Disabling a model prunes its override in the same connection transaction. Other endpoint profiles stay isolated and can be reused if that endpoint is configured again. A profile change does not write or rotate credentials. Providers rebuild only after a successful save.

Context preview, chat, working-agent requests and explicit Continue use the effective profile. Structured skill generation retains its separate per-draft output/timeout override while carrying the selected reasoning adapter. Summary, skill evaluation and preference generation inherit reasoning while retaining their smaller host-side output/time caps. Alternative shells retain their prior settings UX; provider plugins can keep using the existing default trait methods.

Unit, widget and native diagnostics cover wire contracts, unchanged legacy serialization, switching/restart/reset, endpoint isolation, stale and failed writes, provider rejection without secret-body exposure/retry, reasoning output-limit usage and retained files after malformed calls. scripts/test-generation-profiles.py runs save/restore with fresh isolated data and a loopback provider. Live acceptance is recorded separately; deterministic fixtures do not establish general coding competence. Corrupt SQLite recovery, direct thinking-on replay, gateway interoperability and macOS/Linux runtime remain separate acceptance work.
