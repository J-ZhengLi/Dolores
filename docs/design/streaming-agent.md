# Brick 3.4 — Streaming agent replies

Working chats stream each model call's public assistant text, including commentary before approval. Earlier commentary moves into expandable Agent progress; successful replies retain optional `agent.steps` metadata separately from final text. Chat, trajectory and exports preserve this distinction. Provider-supplied reasoning has a separate optional channel: a collapsed Thinking panel and local `agent.thinking` metadata retain at most a 16-KiB latest preview per model call. Full protocol reasoning stays in the provider's bounded continuation cache and does not enter public answers or diagnostic journals.

The provider port adds optional `stream_tool_turn`, defaulting to existing `tool_turn` with one completed-text emission. The OpenAI-compatible adapter requests streaming Chat Completions, function specs, `tool_choice:auto`, `parallel_tool_calls:false` and an optional per-call output allowance. Blank output omits both `max_tokens` and `max_completion_tokens`; explicit settings use the appropriate provider field. It assembles indexed tool deltas and fragmented IDs/names/arguments using the [official contract](https://developers.openai.com/api/docs/guides/function-calling).

Public text and the separate bounded thinking preview cross progress channels; only public text enters assistant answers. Calls become eligible for local validation after a matching finish reason, complete object arguments, contiguous bounded indexes, function types, valid names/IDs and unique IDs. `[DONE]` without valid finish fails; clean EOF after valid finish is accepted. Unfinished frames, interruptions and explicit errors fail. Partial arguments never request approval or invoke tools. Registry, immutable folder scope and single-use approval remain authoritative.

Streaming limits: 2 MiB of wire traffic without decoded progress and 256 KiB per completed frame; there is no cumulative event-count limit. The shared decoder retains a 1-MiB incomplete-frame buffer cap. Existing four-call/four-tool, field, ID/name, context and tool-result limits remain. Public text across all calls shares one 128-KiB budget. Request time now bounds connection startup and inactivity without decoded growth, rather than total active generation. Provider metadata and UI heartbeat ticks do not reset inactivity. Delivery stalls remain bounded and Stop is always available. Blank task time adds no overall deadline; explicit task clocks exclude approval review. No worker/dependency is added.

Each call keeps its last valid usage snapshot, including empty-choices chunks, without summing duplicates. Only explicit pre-stream unsupported-usage-option rejection permits one retry without `stream_options`. Generic rejection, interruption and unsupported format never fall back to plain chat. Side chat remains an explicit user choice.

Final text, commentary, tools and usage commit atomically in schema-6 metadata JSON. Old summaries without `steps` decode to an empty list; no migration/history rewrite occurs. Failure/Stop/exhaustion saves no partial turn and restores the draft. Completed earlier commentary may remain transiently inspectable as Not saved until another chat/run; incomplete current text is discarded. Public commentary returns to the provider with its corresponding calls.

Live model compatibility, OS input/folder-picker UAT, other platforms, accessibility and resource targets remain separate acceptance work.

Protocol reasoning is separately bounded at 1 MiB per turn and 2 MiB across the provider continuation cache. Follow-up request checks include its actual serialized size rather than charging it against the public 128-KiB context budget. UI previews retain the latest 16 KiB with an omission label. Automatic output uses a context-planning reserve of one quarter of the window, capped at 32768 tokens; that reserve is not sent as a generation limit.
