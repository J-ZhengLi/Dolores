# Brick 3.2 — Approved folder discovery

Register three compiled tools against one launch-only opened directory: `read_text_file`, `list_folder {path}`, and `search_text {path,query}`. Use `.` for the chosen folder and relative forward slashes for a subfolder. Each listing/search waits for its own Allow once/Deny before enumeration or content scanning. Search approval explicitly allows scanning bounded eligible files and sharing matching snippets; a later full-file read requires another approval. Bind the displayed query to the invocation and saved record. A denial is cached only for the same tool, resolved folder and query within that run.

Listing is shallow: inspect at most 512 entries, return at most 100 names and at most 16 KiB of serialized results. Sort the bounded inspected subset; disclose truncation without implying it represents the entire folder. Search is literal, case-sensitive single-line text, 1–256 UTF-8 bytes, no regex. Walk at most four levels below the approved scope, inspect at most 256 entries, attempt at most 64 regular-file reads, read at most 256 KiB in total, and accept files up to 16 KiB. Return at most 30 matching lines with snippets up to 240 Unicode characters and at most 16 KiB serialized results. Include scanned/skipped counts and partial/truncation flags. No background indexing or persistent search database.

Reuse the directory capability and path filter. Discovery additionally skips symlinks/junctions and generated/dependency directories (`node_modules`, `target`, `build`, `dist`, `.dart_tool`, `.venv`, `venv`, `__pycache__`). Reject secret/VCS paths and revalidate targets before invocation. The filename filter cannot identify every secret. File contents and names are untrusted data; control-containing names are excluded, and result widgets use literal selectable text. Files can change during a scan. Filesystem work stays on the bounded blocking pool; Stop cancels waiting/checkpoints but cannot preempt an OS call already in progress.

Keep four model calls/four total tools and the existing whole-run/text budgets. A listing → search → read → answer workflow fits four calls. Successful metadata/export stores names, search query/snippets and full approved read results; no absolute folder root or approval is remembered. Schema 5 and ordinary streaming chat remain unchanged.

Reuse approval/result cards and composer geometry. Distinguish listing, search and read, show exact query and scan scope, disclose snippet sharing/storage, and label partial coverage. Verify scoped approval/denial, query binding, Unicode snippets, bounded scans/output, exclusions/links, cancellation, all-tool provider ordering, atomic history/export/restart and compact light/dark layouts. Capability APIs: [Dir](https://docs.rs/cap-std/latest/cap_std/fs/struct.Dir.html) and [DirEntry](https://docs.rs/cap-std/latest/cap_std/fs/struct.DirEntry.html).
