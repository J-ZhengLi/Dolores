# Lifecycle hook qualification

EH09.3 is qualified within the scopes below. The
[hook contract](../design/lifecycle-hooks.md) owns authority, events and limits;
[EH09](../plans/everyday-harness/eh09.md) owns remaining integration gates.

| Evidence | Qualified boundary |
| --- | --- |
| Core configuration | Four-entry/name/argument/path/deadline bounds, typed events and modes, unknown-field refusal and observation-only post-events. |
| SQLite/bridge | Additive schema 49→50 migration, retained chats, revision CAS, reopen and failed-save preservation. Review executes nothing, pins exact script hash/runtime path and refuses changed/expired reviews. Idle-only mutations and missing-script Disable all retain explicit recovery. Plain Windows task paths resolve the same canonical scope as Settings. |
| Windows command fixtures | Required checks refuse before effects; malformed/unknown/oversized output, missing allow, changed scripts and timeout refuse. Stop cancels an owned command. Invocation and cumulative time caps prevent further dispatch. A compaction gate refuses before the wrapped compactor. Observers cannot deny actions through allow:false. |
| Rendered Settings | Compact Light/Dark review, retained failed-save draft/token, explicit retry and Disable all recovery. Status remains reachable above scrolling content. Existing Settings tests retain navigation and draft behavior. |
| Connected normal Windows bridge | Rendered review/Enable produces no script effect. The public loopback model requests a file write: a blocking hook prevents it; a passing check permits it. A malformed after-tool observer retains the created file and saved turn, with error diagnostics in run events. Task-start/completion events run, changed script bytes refuse and explicit Disable all restores ordinary work. Hook messages/output remain absent from provider context. |

Native command fixtures use installed Node and real Windows process ownership;
the connected journey uses public synthetic files and a credential-free loopback
provider. It does not establish real-model competence, arbitrary script/runtime
compatibility, physical pointer/keyboard/IME/accessibility or non-Windows support.
Python shares the command runner but does not have a connected hook journey.

These scripts run with user-account permissions. Top-level script hashes and
runtime paths do not isolate code or pin imported project dependencies. Effects
may remain after failure/Stop; intent without a result requires inspection and
never authorizes replay. Post-hook evidence errors cannot erase the original
tool/turn result. Raw output, receipts and renders remain in ignored output/.

Planning runs exclude command hooks. EH09.5 qualifies shared child hook/budget
ownership and frozen scheduled hook admission, including refusal after Disable.
See [combined lifecycle qualification](harness-lifecycle.md). Broader native input,
migration and real-model journeys remain EH10. H21 remote
supervision stays deferred. Earlier native failure evidence retains its original
boundary; the plain/canonical path mismatch is fixed and regression-tested.
