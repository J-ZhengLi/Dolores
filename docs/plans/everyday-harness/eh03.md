# EH03: goals, checklist, and long-context recovery

Status: complete; EH01/EH02 gates passed (`645805a`, `0774115`).

Design decisions (2026-10-21): core `goal.rs` owns explicit objective, criteria,
constraints, lifecycle, revisioned checklist and cumulative accounting. SQLite
`goals.rs` uses additive migration 41, transactional run claims and attempt
reservations; reopening pauses active goals without replay. Bridge `goals.rs`
adds host controls, a receipt-linked progress tool and the existing Start/admission
route; Flutter `goal_panel.dart` and `chat.dart` arbitrate pending user input before
goal continuation. The goal is created only by the human's explicit Save action.
Completion requires all criteria linked to retained successful tool receipts and
a normally saved final response. Failed/truncated runs cannot complete a goal.

Core `context_recovery.rs`, `agent.rs` and `shared_budget.rs` add safe-boundary
recovery and calm threshold notices. Effective capacity includes the 128 KiB
public context cap and estimated model input allowance with output reserved.
Estimates never become provider usage. Context, response and task budgets stay
separate. Recovery preserves original input, user steering, durable goals and
receipt previews; no historical tool call or approval is executable. Summaries
are bounded untrusted data. Compaction and children consume the same cumulative
goal budget; neither resets it. Deterministic fixtures establish protocol and
recovery only; model-dependent premature stopping needs separate qualification.
