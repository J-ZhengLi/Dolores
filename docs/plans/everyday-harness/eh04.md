# EH04: plan mode and context references

Status: complete; EH02 and EH03 committed (`0774115`, `59d8cc3`).

Design decisions: core `planning.rs` defines versioned human plan decisions and
bounded reference snapshots. SQLite migration 42 adds one chat-owned planning
record with checked revisions; queue/steer receipts freeze that record. Bridge
`planning.rs` provides inspection-only policy, preview/select/remove references
and explicit accepted-revision execution through the existing Start route.
Planning exposes only local read/list/search and human questions, excluding all
commands, delegation, MCP, browser, scheduling and repair tools. Normal tool
permissions still apply after execution starts.

References reuse scoped editor/file and attachment ports plus bounded stored
message pages. Files/code retain selected text, directories share one bounded
listing, terminal/unsaved-code excerpts come from explicit existing attachments,
and cross-chat sources require the same working-folder scope. Preview-to-select
rechecks the source digest; after selection, immutable snapshots survive source
changes/deletion and are clearly labeled historical. Up to four references share
24 KiB (16 KiB each); no recursive expansion. Accepted plans optionally bind the
current goal ID and unchanged checklist, retaining direct human instructions.
Flutter adds plan review and an `@` reference picker beside existing slash
discovery; Save/Accept never start execution and reopen creates no work.
