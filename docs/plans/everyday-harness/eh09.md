Archive contract limits: ZIP input 4 MiB; expanded files 2 MiB total; 512 KiB per
resource; existing SKILL.md 8 KiB; optional manifest 8 KiB; 64 files/128 entries;
relative UTF-8 forward-slash paths within 240 bytes and 12 components. An absent
manifest means schema 1, version `unversioned`, no declared origin/dependencies.
The manifest accepts only schema/version/origin/dependencies. Dependency entries
have name/requirement strings; no setup command or dependency execution is
admitted. File-byte hashes and a sorted, length-framed content hash bind resources
independently of ZIP entry order; a separate archive hash identifies exact input.

### Reviewed installation design - October 24

Own core skill_packages.rs/skills.rs and SessionStore ports, SQLite package
catalogue/schema 49 and skill activation, bridge package storage/commands and
tests. Retain installations in a separate scoped catalogue with at most five
versions per skill and twelve names per scope. Bound the profile's physical
cache to sixty bundles, including unreferenced publications. Refuse capacity
with explicit removal/recovery; do not evict files behind an active snapshot.

Publish bundles under the locked profile, keyed by exact archive SHA-256. Retain
the original ZIP, a host receipt and a payload directory; preserve empty folders.
Use capability directory handles and refuse links, aliases and replacement.
Installation publishes complete bytes before saving catalogue metadata; a failed
save leaves one identifiable bundle for same-archive retry. Installation does
not activate. Activation/rollback stores an optional immutable package snapshot
alongside the existing skill version, with optimistic revision checks and exact
retained package verification. Legacy versions keep absent package metadata.

Review tokens bind session, scope, canonical profile, exact archive and current
catalogue/skill revision. Export retains the original ZIP and refuses overwrite.
Explicit removal first drops only an unreferenced scoped registration; retain
the physical bundle when another scope or skill version references it. For an
unreferenced bundle, delete only verified owned files, preserving the source ZIP
and receipt until payload removal finishes. Failed/partial removal stays visible
as retained data for explicit retry; unknown or changed files refuse removal.
Lists and inspection never activate, grant tools, execute dependencies or replay
work. Qualification includes interrupted publication, failed catalogue writes,
stale reviews, scope/refusal guards, changed resources and safe removal recovery.

The backend also pins package archive identity in composer references and input
submission identity, including after a skill name is forgotten/re-added with the
same document and version numbers. The existing picker carries the full reference;
stale inspection cannot substitute a different package. Runtime source snapshots
retain package identity and resource base without embedding asset bytes in prompts.
