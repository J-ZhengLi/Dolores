## Implementation decisions — October 22

- Start with local-only lifecycle contracts in `crates/dolores-core/src/worktrees.rs` and additive SQLite schema 44 in `crates/dolores-store-sqlite/src/worktrees.rs` / `lib.rs`; expose storage ports from core `lib.rs`. Create the chat, checkout binding and creation intent in one transaction before touching Git. Records survive chat deletion so recovery evidence and filesystem ownership are not lost.
- Freeze the explicit base ref and resolved commit, original checkout, common Git directory, host-owned absolute target, setup policy and UUID. Persist root filesystem identity and Git directory after creation; revalidate them before operations. No automatic setup scripts: Skip or manual setup through the existing reviewed Commands workflow. Failed manual setup retains the checkout and command receipt.
- Use revisioned Creating/Ready/Archiving/Archived/Restoring/Recovery states. Persist intent before external effects. Restart converts in-flight intents to inspection-required recovery; it never repeats Git or setup. Archive snapshots and identity evidence remain available across failures.
- Planned host files: `crates/dolores-flutter-bridge/src/worktrees.rs`, `workspace.rs`, `lib.rs`, `source_control.rs`, with existing supervised `git_process.rs` transport. Bind all tools to the saved checkout, and coordinate repository mutations with existing active-run/Git ownership.
- Planned UI: dedicated `apps/dolores_flutter/lib/worktrees.dart` plus chat/sidebar integration; show concrete source, destination, base and setup policy, retain drafts, and review transfers/removal. Transfer and snapshot/restore design must preserve both sides and pass failure checks before this batch is complete.
- This foundation is not EH06 acceptance. Complete creation/Git integration, ownership serialization, compare/transfer, archive/restore and rendered/native recovery verification remain required. The user's subsequent explicit commit request authorizes a foundation checkpoint while these gates remain open.

### Git creation implementation boundary

Owned host files for this increment: bridge `worktrees.rs`, `worktree_git.rs`,
`worktree_identity.rs`, `worktree_tests.rs`, `lib.rs`, `source_control.rs` and
bridge `Cargo.toml`. Creation is a cancellable background job with a one-use,
chat-bound review of the exact commit and generated target. Git hooks, fsmonitor,
configured filters and submodule recursion are disabled for managed checkout
materialization; manual setup remains a separate reviewed command. Persist an
intent before Git and capture the reserved directory identity before checkout.
Retain interrupted/failed work for inspection; never reset/delete the original
checkout. Root/common-directory identities are filesystem IDs, not path hashes.
