### Reviewed transfer design — October 23

Own bridge `worktree_transfer.rs`, `worktree_snapshot.rs`, transport helpers in
`worktree_git.rs`, worktree job routing/registry and tests; private transfer
receipts; Flutter transfer selection/review/recovery in the
Worktrees panel with focused/native coverage. Source is a Ready managed checkout;
destination is an explicit chat in the same common Git repository. Compare saved
files against the source's frozen base, including committed changes and selected
non-ignored untracked files. Do not copy unsaved editor buffers or grants.

Use a separate host index to capture Git object snapshots without staging the
user's index, then retain source/destination snapshots under owned refs. Generate
literal selected-file binary patches with external diff/hooks/filters disabled.
Check the patch against the destination before review and again before applying;
Git's normal applicability check refuses conflicts without writing either side.
Do not use `--reject` or reset either index/worktree. A conflict exposes both
retained versions and exact paths for manual resolution and a fresh review.
Git documents its default atomic applicability checks in
[git-apply](https://git-scm.com/docs/git-apply), and a host-only index is supported
by [git-read-tree](https://git-scm.com/docs/git-read-tree). Publication may still
fail partway on I/O: save an intent first, retain snapshots and patch, mark an
uncertain/recovery result and never replay on restart. Completed transfer leaves
the destination index and unrelated changes intact. Limits and omissions are
explicit; over-limit selection retains files and offers smaller selection.

Retain transfer receipts in a host-owned `worktree-transfers/<uuid>/` directory
beside managed checkouts. Write and flush separate immutable review, intent and
result files before/after publication, with exact patch and numbered raw file
backups. This puts recovery artifacts and their manifest together and avoids a
new SQLite migration just to point at files. Lifecycle ownership remains in the
existing SQLite worktree record. Listing is bounded and remains independent of
chat deletion. An intent without a result is uncertain after restart; inspection
never applies it. Source/destination object trees and index trees have owned Git
refs; original raw index bytes are also retained. Do not delete recovery data on
review dismissal or failed publication. Any future cleanup must be explicit.

Concrete files are `lib/worktree_transfer.dart`, existing `lib/worktrees.dart`,
`test/worktree_transfer_test.dart` and `test/native_worktrees_ui_test.dart` in the
Flutter app; bridge `worktree_transfer.rs`, `worktree_snapshot.rs`,
`worktree_transfer_tests.rs`, `worktree_tests.rs`, `worktree_git.rs`, `worktrees.rs`,
`terminal.rs` and module wiring. Apply refuses active terminals in the common
repository and unsaved selected editors. Changed evidence/backups are refused;
Windows file pins protect retained bytes during publication. The actual workflow
must pass the normal native bridge, not only a mock, before EH06.3 is checked off.

tests, analysis, all-target Clippy and the normal Windows build pass. The broad

### Archive and restore design — October 23

Owned files: bridge `worktree_archive.rs`, `worktree_archive_tests.rs`, shared
snapshot/Git helpers, worktree routing/registry, terminal/language ownership
inspection and module wiring; scoped SQLite full-storage errors and quota recovery tests;
Flutter archive review/restore/inspection controls
in `worktrees.dart` with focused/native journey tests; core lifecycle tests and
acceptance/UI/changelog records. No applied SQLite migration is changed.

Archive review captures every direct regular file, including ignored files, plus
empty directories, raw staging bytes and the actual HEAD. Reject aliases, nested
repositories/submodules, unavailable roots and over-limit inventories before
removal. Raw bytes and manifests are flushed outside the checkout; an owned Git
snapshot commit/ref also retains the archive objects. Recheck the complete
inventory and exact ownership before saving Archiving, then remove only the
verified UUID checkout through supervised Git. Never remove the original checkout.
Archive/restore require idle repository work, saved editors, stopped terminals
and released language-service ownership. Errors keep concrete evidence paths.

Restore requires the exact target to be absent and the archive/ref/manifest to
validate. Persist Restoring before reserving a new directory. Save its new
filesystem identity before Git materialization; setup stays skipped. Retain an
explicit per-file restore plan with before/after digests before publication;
existing unrelated bytes refuse rather than being overwritten. Resume is an
explicit reviewed action: after-bytes are skipped, before-bytes can be restored,
other bytes require manual recovery. Preserve the original staged/unstaged split,
binary files, ignored files and directory/file permissions. Save Ready only after
verification. Restart marks in-flight state for inspection and never replays it.

Use the existing 64 MiB/20,000-entry bounded snapshot policy, including all ignored
data in the archive's bound, with a bounded 16 MiB manifest/restore plan. Larger
or unsupported trees remain in place with narrowing/external-backup guidance.
Exercise interruption before/after Git registration, publication/save failures,
changed ownership, occupied restore targets, stale reviews, failed manual setup
and bounded storage pressure. The quota fixture produces actual SQLITE_FULL without
filling the host drive; physical whole-volume exhaustion during Git is separately
unqualified. Required native and failure/recovery checks pass; broader resource
qualification remains recorded for EH10.
