## Batch acceptance

### Review finding design — October 23

Implement EH07.1 first. Own core `review_findings.rs` and `SessionStore` ports;
SQLite `review_findings.rs` and an additive schema 45 migration; bridge
`review_findings.rs`, command routing and real-Git tests; Flutter review controls
in Source Control and its diff renderer, with focused/rendered/native tests.
Preserve unrelated source edits and do not alter applied migrations.

Capture anchors from a host-validated displayed comparison: checkout root,
repository identity, file path, working/staged/commit basis, exact commit where
applicable, revision, complete patch digest, left/right side, line and bounded
literal excerpt. Validate that the selected line is in the displayed page before
saving. Findings have stable IDs, optimistic revisions, bounded text and explicit
open/submitted/resolved states. Reopening reads evidence without invoking tools.
Mark changed comparisons stale; retain the original excerpt and allow explicit
reselection. Do not silently move comments to a guessed line.

Selected findings become ordinary EH01 queue or steering input with frozen
anchors and review IDs. Persist submission and its input in the same transaction;
failed saves preserve findings, draft and pending input. Repeated submission IDs
must not enqueue duplicates. Queue limits, Stop and uncertain delivery retain
their existing meaning. A submitted finding is not fixed merely because delivery
was acknowledged. Explicit resolution records a later host-observed comparison
and the user's assessment; no model message alone marks a finding resolved.

Use 128 retained findings per chat, 4 KiB finding text and 2 KiB anchor excerpts,
with bounded pages and a clear capacity recovery action. No automatic deletion of
saved findings. Removal is a deliberate local record action; it never edits files
or cancels an already submitted instruction. Shared-folder and managed-checkout
contexts retain their actual root and normal admission/tool permissions.

EH07.2–EH07.3 reuse the existing `thread_context.origin`, completed-turn fork,
message timestamps/attachments and explicit context snapshots where possible.
Side chats share only the selected bounded excerpt; return navigation and a
separate bring-back action never dispatch on opening. Edited prompts create a
new branch and draft, preserving the original and prior external-effect receipts.
Neither path copies active approvals, goals or pending input. Freeze the exact
branch/worktree integration after inspecting those existing flows; this review
increment does not claim those remaining tasks.

### Review persistence increment

Core and SQLite contracts are implemented first, without adding a public bridge
command or UI in this increment. Additional owned files are SQLite
`task_inputs.rs` (extract the existing queue edit into a caller-owned transaction)
and the existing worktree migration test (assert the current schema version).
Both normal input and finding submission reuse the same admission, planning/skill
snapshots and queue limits. Finding submission keeps the composer draft even if
its text equals the generated instruction. The submission ledger and selected
finding revisions commit with the input or all roll back. An exact repeated
submission ID returns its existing receipt; another instruction's ID is refused.
Resolved notes require explicit reopen before editing. Findings keep up to sixteen
submission references and removal preserves already queued input and snapshots.

Credential-free tests exercise record ownership, stale edits, atomic save failure,
queue capacity and ordering, uncertain delivery after reopen, exact retry versus
ID collisions, duplicate/oversized selections, later-revision resolution,
bounded pagination/capacity recovery and version-44 migration with retained chat
history/draft. EH07.1 stays unchecked until host capture, rendered controls and
the normal native flow are delivered and verified.
