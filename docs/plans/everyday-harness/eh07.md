### Linked side conversation design — October 23

Own core `side_conversations.rs` and storage ports; SQLite
`side_conversations.rs` using existing `thread_context.origin` and durable
planning references; bridge `side_conversations.rs` and command routing; Flutter
`side_conversations.dart`, reply selection, chat/controller, AppHost navigation
and focused/rendered/native tests. No applied migration is changed. Link the
previous review-flow delivery at `f90711a`.

Ask about this operates on selected saved message text. A host preview binds the
parent/message ID and SHA-256 of canonical source to the selected rendered text;
the latter is explicitly labeled a user-selected rendered excerpt, not a proven
canonical byte range. Creation rechecks the source digest and atomically creates
a separate Side chat with only that frozen context reference and an optional
question draft. It does not start a run or copy parent history, attachments,
skills, goals, queue entries, thread settings, approvals or folder access. Parent
and side tasks keep separate ordinary owners; switching views does not stop them.
Existing shared-folder forks stay compatible. Explicit folder/worktree branching
remains EH07.4, rather than silently granting it to a selected-text side chat.

The retained origin includes parent title/identity, source identity/digest,
selected excerpt, initial question and bounded return receipts. Source/parent
deletion leaves the frozen excerpt readable and offers an actionable unavailable
return state. Creation IDs are stable across failed replies, so retry never
overwrites an existing chat or its newer draft. Context is stored independently
of model summaries and remains inspectable after compaction/reopen.

Bring to parent previews a selected saved assistant conclusion. Queue or Steer
is an explicit sharing action; opening that preview never dispatches. Validate
child ownership, source digest and the retained parent, then commit the normal
EH01 input and return receipt in one transaction without consuming either draft.
Exact retries inspect the existing receipt, never duplicate input. Stop/paused
state, parent budgets, context limits and live-input restrictions remain in force;
the normal parent owner decides dispatch. Returning a conclusion is not evidence
that the parent goal is complete or permission to replace it.

Bounds: 8 KiB selected excerpt, 4 KiB optional question, 1 MiB canonical source
inspection, 32 KiB encoded origin and 32 return receipts per side chat. The normal
16 KiB combined input and eight-pending-input limits still apply; over-limit
sharing keeps the selection/drafts and offers narrowing or a new side discussion.
Verify failed atomic creation/return, stale/deleted source, duplicate delivery,
full/paused parent queue, preserved parent goal/draft, and native selected-text
navigation/return. This increment leaves EH07.3–EH07.4 open.

### Managed-worktree branch design — October 24

Start EH07.4 from edited-prompt delivery `9487a3f`. Own core prompt-branch
folder/request/retained-target contracts; SQLite prompt-branch target admission
and archive compatibility tests; bridge prompt-branch target validation and
existing-owner admission; Flutter prompt editor and an optional selection mode
of the existing Worktrees inspector; focused/rendered/native tests, user guide
and acceptance. Reuse EH06's review, exact base commit, creation jobs, checkout
pins, setup policy and interrupted-creation inspection. No new Git runner,
automatic hook/setup execution, applied-migration change or background dispatcher.
Use `worktree_prompt_branch_tests.rs` under the existing real-Git worktree
fixture to check source staging, target admission and active-owner refusal.

Choose **Share current folder**, **Managed worktree**, or **No working folder**
in the edited-prompt editor. The managed choice opens the existing Worktrees
review/creation workflow as a picker, retaining the prompt editor beneath it.
Creation is a deliberate separate action: a new checkout starts at its reviewed
commit; the source's dirty files and staging remain there. Choosing its empty,
Ready chat returns its identity/revision to the prompt editor without opening or
running that chat. Existing tasks with work are not eligible for adoption.

Opening the edited branch atomically attaches the frozen transcript, edited
draft, optional attachments/context and ancestry to that new empty task. The
store verifies that the selected managed record is still Ready, unchanged and
bound to the source repository/folder, and that no history, draft, goal, queue,
skills, plan, thread settings, runs or file-effect ownership would be overwritten.
The host rejects active owners, validates/pins the checkout through the existing
EH06 boundary, and keeps its actual target workspace. Do not accept a frontend
folder path as a grant. Save the reviewed target snapshot in the bounded archive;
keep older Shared/Side archives readable with no schema change.

This is intentionally two explicit local steps, not a pretend cross-filesystem
transaction. If creation or final attachment fails, keep the managed checkout,
its saved lifecycle evidence, source chat and edited text. Inspect/reconcile
creation through Worktrees, then retry attaching to the same eligible identity;
never recreate Git work automatically or delete the retained checkout. Lost
attachment replies inspect the exact saved branch request. A newer target draft,
revision change, unavailable folder, another repository or occupied task refuses
without replacing either version. The original prompt's old effects remain
historical; a new worktree's committed files are not those historical effects.

Verify both explicit Shared/Managed flows with source dirty/staged work intact,
wrong/reused/active targets, stale revisions, failed final transaction followed by
same-target retry, independent subsequent task/file changes, archive/reopen and
older prompt-branch JSON. Review finding staleness continues to use EH07.1's
checkout/revision checks; do not transplant findings onto another checkout.
EH07.4 stays unchecked until these recovery and native gates pass.
